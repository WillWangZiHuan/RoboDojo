# Astra 旧轮：基础设施中断，不是主动提交

试次 `astra_20261028_002`，模型 GPT-6 Astra，Slurm 48825。模型自行提出“七色门”，使用同一七块初态、cuRobo/关节工具、真实坐标和三路图像。此轮使用旧 SSH+srun 传输，未使用新轮统一的持久仿真及 600 秒恢复条件，不与新三模型轮次混算。

## 实际结果

53 次模型工具请求全部收到回复；原生记录 7,650 次低层动作、15,474 个物理步、0 次重置。第 14 号工具请求报告规划失败，此编号从 0 起。模型随后继续操作，也对接触导致的方块漂移重新定位。工具请求数与底层动作数不是同一单位。

最终画面可见红、橙、黄组成三层，绿、蓝组成两层，紫和白仍在桌面，未形成完整门形。模型最后公开说明准备处理紫块与白色顶块；它没有调用 submit。服务端 episode 状态为 interrupted，原因 `input closed without submission`，submission 为 null。Slurm 退出码 0:0 仅表示进程正常退出，不证明任务完成。

模型停止新输出后，恢复旧进程链导致仿真输入关闭。独立小请求仍可返回，原长历史连接出现 Broken pipe；网络波动或长上下文传输是待查因素，根因未确认。后续新轮独立保留，不拼接为本轮的继续完成。

## 录像与图像审计

三路原始 MP4 各 1,548 帧、25 fps、61.92 秒，保留全部按既定频率采样的物理运动，均完整解码并核对哈希。现实时间版从首次场景记录到最后观察跨度 11,443.572 秒（约 3 小时 10 分 44 秒），模型或规划等待时保持上一物理帧；64 倍观看版约 179 秒。该现实时间范围止于最后观察，不包含其后直到进程退出的静态等待。原视频的仿真时间不能当作模型总耗时。

已检查原视频六处采样画面及最终 PNG；这不是逐帧人工检查。实际原生模型工具输出中的 159 张输入图逐张 SHA-256 均匹配保存的桥接 PNG。另有工程接管观察，全部本地相机图共 168 张；工程观察不算原模型收到的图。
